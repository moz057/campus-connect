The published app is a browser demo. Real accounts, shared records, and uploads become available after you connect and rebuild with your Supabase project.

Start with the structure

├── src/
│   ├── components/  # Navigation, event cards, QR tickets
│   ├── contexts/    # Auth, data, toast messages
│   ├── data/        # Browser-only sample data
│   ├── lib/         # Supabase, types, validation, CSV
│   └── pages/       # Student & organizer workflows
├── supabase/
│   ├── schema.sql   # Tables, RLS, RPCs, storage
│   ├── seed.sql     # Optional sample events

1. Create the backend

  1. Create a new project at Supabase.
  2. Run schema.sql once in the new project's SQL Editor. It creates all five tables, relationships, indexes, security policies, registration/check-in functions, and image buckets.
  3. Enable email/password authentication. Set the Authentication Site URL and allowed redirect URLs for localhost and your production domain.
  4. Optionally run seed.sql for example events.

2. Run the frontend

Unzip the source. Use Node.js 22.12+ and npm.

cd campusconnect
npm install
cp .env.example .env.local

Copy the public project URL and publishable (or legacy anon) key from Supabase into .env.local:

VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_KEY

Never put a service-role key or database password in the frontend.

npm run dev

Open the URL Vite prints. Without these variables, you can explore student and organizer demo roles at /login.

3. Approve an organizer

Sign up and verify the organizer's email first. As the database owner, replace the address and run:

update public.profiles p
set role = 'admin'
from auth.users u
where p.id = u.id
  and lower(u.email) = lower('organizer@usc.edu.ph');

Log out and back in to load the role. Students cannot grant themselves organizer access.

4. Validate and deploy

npm test
npm run build

Deploy dist/ with an SPA fallback to index.html. Vite variables are injected at build time; rebuild after changing them. Use HTTPS for camera scanning.

Verification: 27 automated checks cover simulated student/organizer workflows, input validation, CSV safety, and PostgreSQL authorization and registration rules. Browser appearance, live Supabase email/storage, concurrent multi-connection load, and physical camera behavior need acceptance testing in your environment.
